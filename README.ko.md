# anchor-review

**ACL·EMNLP·NAACL(ARR) 기준의 보정된 블라인드 모의 심사 Claude Code 스킬**

[English README](README.md)

LLM 심사자가 매긴 절대 점수는 믿기 어렵지만, 논문들 사이의 순서는 비교적 잘 맞힙니다. anchor-review는 이 점을 이용합니다.

- 내 원고를 같은 분야에서 결과가 알려진 논문(앵커)과 섞어 블라인드로 심사합니다.
  - 본 학회 논문
  - Findings 논문
  - arXiv에만 있는 논문
- 결과는 내 원고가 앵커들 사이에서 어디에 놓이는지로 보고합니다.
- 같은 실행에서 심사자들이 앵커의 클래스를 얼마나 잘 구별했는지도 함께 계산합니다. 그래서 결과마다 신뢰도가 따라 나옵니다.

| 기본 프리셋: ARR × RAG·문맥 압축·다중 홉 QA | 조정용 24편 | **검증용 12편** |
|---|---|---|
| 채택(본 학회+Findings) vs arXiv만 AUC | 0.84 | **0.89** |
| 본 학회 vs Findings AUC | 0.30 | 0.63 (4편 대 4편) |

**구분할 수 있는 것:** 채택권에 들어가는지 아닌지.

**구분할 수 없는 것:** 본 학회와 Findings. 이 둘은 원고 내용보다 할당량과 심사자 운에 더 좌우되기 때문입니다. 보고서에도 이 한계를 매번 적습니다.

## 작동 방식

**1단계: 실제 논문으로 기준 잡기 (학회 × 분야마다 한 번)**
- Claude가 사용자 분야에서 결과가 알려진 논문을 모읍니다.
  - 기본값은 본 학회 12편, Findings 12편, 조금 쉬운 학회(COLING) 채택 6편, arXiv만 12편입니다.
  - arXiv만 논문은 arXiv, Semantic Scholar, OpenAlex, Anthology 대조, 웹 검색으로 게재 기록이 없는지 확인합니다.
- 분석 담당이 클래스별로 결과를 아는 상태에서 읽고 공통점을 기록합니다.
  - 기여 유형과 크기
  - 근거의 폭
  - 어떤 결함이 있어도 채택됐는지
- 종합 단계에서 심사자 등급별 기준서를 만듭니다.
  - ARR 공식 척도를 따르고, 그 학회에서 어떤 특징이 몇 점을 받았는지 적습니다.
  - 논문 제목은 넣지 않습니다.

**2단계: 블라인드 심사 (원고마다)**
- 내 원고를 기준 논문과 섞어 **10편 묶음**을 만듭니다.
  - 구성: 원고 + 본 학회 3, Findings 2, COLING 2, arXiv만 2
  - 저자, 학회 표시, 한계·윤리·AI 사용 절을 지우고, 필요하면 방법 이름도 바꿉니다.
- **학회 등급별 심사자 3명이 자기 등급 기준서로 10편을 모두** 심사합니다.
  - 목표 학회(ACL)
  - 같은 급(EMNLP)
  - 조금 쉬운 학회(COLING)
- 논문 점수는 **3명 평균**입니다.
- 보고 내용
  - 내 원고 순위
  - 전체 순위표(등급별 점수와 이유)
  - 내 원고 상세 심사평: 주장별 근거 판정, 강점, 약점과 심각도, 질문, 점수를 올릴 방법, 등급 간 이견
  - 신뢰도: 등급별로 기준 논문을 얼마나 잘 구별했는지

심사자는 목적도, 내 원고가 섞여 있다는 사실도, 일부가 게재 논문이라는 사실도 모릅니다. 웹 검색은 금지입니다.

## 기본값과 직접 설정

| 원하는 것 | 하는 방법 |
|---|---|
| 바로 심사만 | 내장 기준서(`presets/criteria/acl-rag/`, ACL 등급 × RAG 분야)로 2단계만 실행 |
| 학회, 분야, 논문 수, 등급, 심사자 수, 묶음 크기를 바꾸고 싶음 | `config/default.json`을 `~/.claude/anchor-review/config.json`으로 복사해 고친 뒤, 1단계부터 실행 |

대략적인 비용
- 1단계: 서브에이전트 약 5개(분석 4 + 종합 1)가 논문 약 40편을 한 번 읽습니다.
- 2단계: 심사자 3명 × 10편입니다.

## 설치

```text
/plugin marketplace add sungchul02/anchor-review
/plugin install anchor-review@anchor-review
```

또는 `skills/anchor-review/` 폴더를 `~/.claude/skills/`에 복사합니다.

## 사용 예

```text
paper.md를 EMNLP 기준으로 anchor-review 해 줘. 기본 RAG 앵커를 써.
```

```text
내 기계번역 원고를 ACL 기준으로, 같은 분야 본회의·Findings·arXiv만 논문과 섞어 블라인드 심사해 줘.
```

### 점수 읽는 법 (기본 프리셋)
| 3명 평균 Overall | 해석 |
|---|---|
| 3.0 이상 | 채택권. arXiv만 앵커 12편 중 1편만 여기에 들었음 |
| 2.5~2.99 | 경계 |
| 2.5 미만 | 지금 상태로는 탈락 가능성이 높음. 채택 앵커 24편 중 4편만 여기에 있었음 |

실제 ARR 심사자의 평균은 약 3.2이고, 이 심사자들은 그보다 낮게 줍니다. 점수 자체보다 앵커들 사이의 위치를 보세요.

## 한계

- **등급별 방식은 아직 한 번만 확인했습니다.**
  - 10편 묶음에서 AUC는 전체 0.79였습니다(EMNLP 등급 0.96, ACL 0.64, COLING 0.68).
  - COLING 기준서는 6편에서만 만들어져 너무 엄격했습니다. 그래서 이 등급의 결과는 잠정치로 보세요.

- 앵커는 한 분야 36편뿐입니다.
- "arXiv만"은 게재 기록이 없다는 뜻이지, 탈락이 확인됐다는 뜻은 아닙니다.
- 심사자는 LLM입니다.
  - 지표 불일치, 불공정한 비교, 누락된 세부처럼 꼼꼼한 심사자가 짚을 결함은 잡아냅니다.
  - 할당량이나 심사자 배정 운은 반영하지 못합니다.
- 기준 논문의 원문과 목록은 배포하지 않습니다. 새로 설정할 때마다 Claude가 사용자 분야에 맞춰 모읍니다.
- 제출 전 점검용입니다. 지도교수나 실제 심사를 대신하지 않습니다. 남의 투고 원고를 심사하는 데 쓰지 마세요.
